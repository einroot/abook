# AGENTS.md — заметки для инженера Kilo

## Исправление: resumeLastPlayedBook не должен запускать playBook с пустыми параметрами

**Файл:** `TtsPlaybackService.kt`
**Строка:** 1199

### Суть проблемы

Метод `resumeLastPlayedBook()` (стр. 1178) запускал внешнюю корутину через `serviceScope.launch`, внутри которой вызывал `playBook()` с явными числовыми значениями (`chapterIndex = 0`, `charOffset = 0`) благодаря оператору `?: 0`. `playBook()` внутри себя же вызывал `currentLoadJob?.cancel()`, который отменял внешнюю корутину и создавал свою собственную внутреннюю. В результате:

1. Проверки `currentBookId == null || chapters.isEmpty()` в точках вызова `resumeLastPlayedBook()` (строки 1090, 1266) теряли смысл — `playBook()` вызывалась **обязательно** с числовыми аргументами.
2. Если пауза приходила во время загрузки, отменялся только внутренний `job`, а внешний оставался и мог перезапустить пайплайн.
3. Возникала двойная вложенность корутин в одном `currentLoadJob`.

### Исправление

Добавлена повторная проверка **внутри** корутины `resumeLastPlayedBook()` **перед** вызовом `playBook()` (строка 1199):

```kotlin
if (currentBookId != null && chapters.isNotEmpty()) return@launch
```

Оператор `&&` (И): единовременно только если и `currentBookId` установлен, И `chapters` заполнены — то есть когда пайплайн уже завершил загрузку и повторный запуск не нужен. Все остальные комбинации (`null + []`, `не-null + []`, `null + [...]`) пропускают проверку и идут к `playBook()`.

Теперь пайплайн продолжается только если состояние не изменилось — то есть в момент, когда `playBook()` единственно может что-то загрузить. Если за время асинхронного чтения из БД состояние успело измениться (книга уже загружена, главый список не пуст), вызов пропускается.

Это гарантирует, что `playBook()` всегда создаёт **один единственный** `currentLoadJob` и больше не происходит вложенности запусков.

### Пустые параметры

Значения `pos?.chapterIndex ?: 0` и `pos?.charOffsetInChapter ?: 0` оставлены без изменений в этой версии исправления. Основная проблема была не в передаче нолей, а в двойном `serviceScope.launch`. Если в дальнейшем понадобится передача `null` вместо `0`, можно дополнить сигнатуру `playBook` поддержкой nullable-параметров.
